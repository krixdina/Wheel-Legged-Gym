# sim2sim 偏航漂移问题 纠错文档

本文记录"机器人在 sim2sim 中无转向指令却持续转圈"问题的完整排查过程：现象、
定位实验、根本原因、已验证的修复方案，以及对其中关键概念（对称观测、对称策略、
镜像等变性测试、镜像算子）的逐项解释和推导。

数据来源：两段 sim2sim 参考轨迹（由 `reference_data/collect_reference_data.py` 采集）：

- `Jun09_19-30-50_vx0p00_wz0p00_h0p18_t60s`：从倒地到站立（vx=0, wz=0）。
- `Jun09_19-33-32_vx1p20_wz0p00_h0p18_t60s`：从倒地到站起再匀速前进（vx=1.2, wz=0）。

机体坐标系约定（与 `状态量与动作量说明.md` 一致）：`+x` 前方、`+y` 左侧、`+z` 上方；
偏航角速度 `base_ang_vel_z > 0` 表示**左转**（绕 +z 逆时针）。

---

## 1. 现象（从数据复现）

把两段轨迹的 `base_ang_vel_z`（偏航角速度）按时间前/中/后三段取均值：

| 工况 | `base_ang_vel_z` 均值 | 早 / 中 / 晚三段 | 性质 |
|---|---|---|---|
| STAND（vx=0） | +0.036 rad/s | 0.076 → 0.021 → 0.010 | **衰减**，更像站起恢复后的残余漂移 |
| FWD（vx=1.2） | **+0.40 rad/s** | 0.39 → 0.41 → 0.41 | **完全不衰减**的系统性左转 |

正值即左转，与"前进时持续向左偏"的观察吻合。FWD 60 s 累计偏航约 +24 rad。

进一步看 FWD 的左右轮：轮速幅值固定不对称 `|wheel_vel_R|≈29.3 > |wheel_vel_L|≈26.5`
（右轮快约 10%），右侧线速度更大→整体左转。而且这是**策略主动指令的**：
原始动作 `raw L_wheel=+4.40, raw R_wheel=-4.94`，两者之和 -0.54（直行本应≈0）。

**核心悖论**：27 维观测里**包含** `base_ang_vel_z`（偏航率）与 `command_wz=0`，
策略本应据此闭环把偏航纠回 0，却稳定维持 0.40 rad/s 不纠正。

---

## 2. 定位实验（三步，层层排除）

排查思路：转圈 = 左右不对称。不对称只可能来自三处之一：**仿真喂进的观测**、
**策略网络本身**、**机器人模型**。逐一用实验排除。

### 2.1 实验一：对称性探针（symmetric-obs probe）

**做了什么**：手工构造一个**完全左右对称**的观测，喂给策略，看输出动作是否对称。

> **什么是"完全左右对称的观测"？**
> 不是让 27 个数全相等，而是让观测中**左右成对的量数值相同、且无任何偏航信息**，
> 即这个状态在物理上"左右完全镜像、机体不转、不歪"。具体构造为：
> - `base_ang_vel = [0,0,0]`（不转）、`projected_gravity = [0,0,-1]`（不歪，纯竖直）
> - `command = [vx, 0, height]`（`wz=0`，无转向指令）
> - `theta0 = [a, a]`、`theta0_dot=[0,0]`、`L0=[b, b]`、`L0_dot=[0,0]`（左右腿状态相同）
> - `wheel_pos=[0,0]`、`wheel_vel=[c, -c]`（轮子镜像安装，左右轴反向，所以"对称"
>   意味着幅值相同、符号相反）
> - `last_actions` 取对称值
>
> 取的 `theta0≈-0.22, L0≈0.17` 等来自 FWD 实测，保证观测落在策略训练见过的分布内。

> **什么是"对称的策略输出"？**（判据）
> 因为左腿在 `leg_states` 里已做了镜像去负（左腿取负），左右腿在同一套 VMC 坐标系下，
> 所以腿部对称输出应满足 `Lθ==Rθ`、`Ll0==Rl0`；轮子因镜像轴，直行对称输出应满足
> `Lw == -Rw`，即 `Lw+Rw==0`。任何非零的 `Lθ-Rθ` / `Ll0-Rl0` / `Lw+Rw` 就是
> 策略**注入的转向偏置**。

**结果**（完全对称观测输入 → 实测动作输出）：

| 工况（对称输入） | `Lθ-Rθ` | `Ll0-Rl0` | `Lw+Rw` |
|---|---|---|---|
| STAND vx=0, θ0=-0.13, L0=0.20 | -0.0094 | -0.0612 | **+0.1506** |
| FWD vx=1.2, θ0=-0.22, L0=0.17 | +0.0603 | +0.0129 | **+0.0890** |
| FWD-b vx=1.2, θ0=0.0, L0=0.20 | +0.0063 | -0.0090 | **+0.2222** |

`Lw+Rw` 恒为正、`Lθ-Rθ`/`Ll0-Rl0` 非零：**给完全对称的输入，策略却输出不对称的动作。**
说明偏置**不来自仿真喂进的数据**，而在策略内部。

### 2.2 实验二：镜像等变性测试（mirror-equivariance test）

实验一是"对称输入→看输出"。实验二更严格、更量化：直接检验网络是否满足**镜像等变性**。

> **什么是镜像等变性？**
> 一个左右对称的控制器应当满足：先把世界镜像、再决策，等于先决策、再把决策镜像。
> 形式化：设 `M_obs` 是作用在观测上的左右镜像算子，`M_act` 是作用在动作上的镜像算子，
> `π` 是策略网络，则**等变**意味着
> ```
> π(M_obs · obs) == M_act · π(obs)      对任意 obs 成立
> ```
> 直观理解：把机器人左右翻转（连同它看到的世界一起翻转），它应当做出"原动作的左右翻转版"。
> 一个真正左右对称的控制器必然等变；普通 MLP 没有任何机制保证这一点。

> **镜像等变性 ≠ 实验一的"对称输入对称输出"。**
> 实验一只测了对称这一个特殊点（不变性，invariance），实验二测的是**任意**观测下的
> 等变性（equivariance），覆盖面更广、更能定量刻画网络整体有多不对称。

**做了什么**：随机采样 2000 个合理观测 `o`，计算等变性误差
`‖ π(M_obs·o) − M_act·π(o) ‖`，与动作向量本身的典型模长作比较。

**结果**：

```
动作向量典型模长          ≈ 1.673
镜像等变性误差 mean       = 3.2435   median = 2.9422   max = 10.8174
```

误差均值 3.24 **比动作本身还大**。网络**完全不具备左右对称性**。
（随机观测偏 OOD 会放大数值，但与实验一的分布内结论一致、互相印证。）

### 2.3 实验三：模型排除（MJCF 对称性）

直接读 `robot/wheel_legged_fyt_whole.xml` 比较左右 body 的质量与惯量：

```
left_thigh / right_thigh : mass 差=0.00e+00, inertia 差=0.00e+00
left_leg   / right_leg   : mass 差=0.00e+00, inertia 差=0.00e+00
left_wheel / right_wheel : mass 差=0.00e+00, inertia 差=0.00e+00
```

**模型完全左右对称**，排除"模型不对称导致偏置"。

> 注意：实验一、二都是**模型无关**的纯网络测试（只调用 `policy.act`，不跑仿真），
> 所以策略不对称这一结论独立于模型成立；实验三只是把模型这条路也堵死，让答案完整。

## 3. 根本原因

综合三个实验：

> 训练出的策略是一个普通 MLP，**未做任何左右对称约束**，因此
> `π(镜像观测) ≠ 镜像(π(观测))`——网络对左右通道学到了略有差异的权重，带有一个
> **内在转向偏置**。同时，策略**只感知偏航角速度 `yaw rate`，不感知绝对航向 `yaw angle`**。
> 单靠角速度反馈无法把航向漂移压到零，只能收敛到一个"内在偏置 = 反馈回正力"相互平衡的
> **非零均衡偏航率**，宏观上就是匀速画圈。

这也解释了**为什么速度越快转得越凶**：同样比例的左右轮速不对称，乘以更大的轮速绝对值，
就是更大的左右线速度差→更大的偏航（站立约 0.10 rad/s；1.2 m/s 时升到约 0.36~0.40 rad/s）。

---

## 4. 修复方案：推理时镜像对称化

核心思路：网络不对称，那就在推理时**人为地把它对称化**——把"策略本身"与"策略的镜像版"
取平均，强制让合成策略满足镜像等变性，从而内在转向偏置被抵消。

### 4.1 对称化公式

```
a_sym = ½ · [ π(obs) + M_act⁻¹ · π(M_obs · obs) ]
```

`M_act` 是对合算子（自身的逆等于自身，`M_act⁻¹ = M_act`），所以实现上就是：

```
a       = π(obs)                       # 正常前向
a_mir   = M_act( π( M_obs(obs) ) )     # 把观测镜像→前向→再把动作镜像回来
a_sym   = 0.5 * (a + a_mir)
```

代价仅多一次前向推理。合成出来的 `a_sym` 严格满足 `a_sym = M_act·π_sym(M_obs·obs)`，
即对称化后的策略**精确等变**，内在偏置为 0。

### 4.2 镜像算子 M 的推导

镜像是"机器人连同它看到的世界绕机体 x–z 平面（前–上平面）做左右翻转"。按每个物理量
在该翻转下的变换规则，逐分量推导（下标对应 `controller.build_observation` 的 27 维布局）：

| 物理量 | 观测下标 | 翻转规则 | 依据 |
|---|---|---|---|
| `base_ang_vel_x`（roll 率） | 0 | **取负** | 角速度是赝矢量；绕 x–z 平面镜像，x 分量变号 |
| `base_ang_vel_y`（pitch 率） | 1 | 不变 | 赝矢量 y 分量在该镜像下不变 |
| `base_ang_vel_z`（yaw 率） | 2 | **取负** | 赝矢量 z 分量变号（左转↔右转） |
| `projected_gravity_x` | 3 | 不变 | 真矢量，镜像across x–z 平面只翻 y |
| `projected_gravity_y` | 4 | **取负** | 真矢量 y 分量变号（左歪↔右歪） |
| `projected_gravity_z` | 5 | 不变 | |
| `command_vx` | 6 | 不变 | 前进命令不随左右翻转改变 |
| `command_wz` | 7 | **取负** | 转向命令左↔右 |
| `command_height` | 8 | 不变 | 标量高度 |
| `theta0_{L,R}` | 9,10 | **左右交换** | 左右腿互换 |
| `theta0_dot_{L,R}` | 11,12 | **左右交换** | 同上 |
| `L0_{L,R}` | 13,14 | **左右交换** | 同上 |
| `L0_dot_{L,R}` | 15,16 | **左右交换** | 同上 |
| `wheel_pos_{L,R}` | 17,18 | **交换并各取负** | 见下方"轮子为何要取负" |
| `wheel_vel_{L,R}` | 19,20 | **交换并各取负** | 同上 |
| `last_action` 腿部 `Lθ,Ll0 ↔ Rθ,Rl0` | 21,22 ↔ 24,25 | **左右交换** | |
| `last_action` 轮 `Lw ↔ Rw` | 23 ↔ 26 | **交换并各取负** | 与轮速同理 |

> **轮子为何"交换并取负"？**
> 数据显示直行前进时 `wheel_vel_L=+26.5, wheel_vel_R=-29.3`（符号相反），说明左右轮
> 关节轴**镜像反向安装**。做左右翻转后，物理前进仍要前进（vx 不变），新左轮 = 原右轮，
> 而原右轮在前进时读数为负、新左轮却该读正，所以映射是"交换后再各取负"：
> `(wL, wR) → (-wR, -wL)`。轮位置、轮的 `last_action` 同理。

动作算子 `M_act` 同构：腿部左右交换、轮部交换并取负：

```
M_act([Lθ, Ll0, Lw, Rθ, Rl0, Rw]) = [Rθ, Rl0, -Rw,  Lθ, Ll0, -Lw]
```

代码形式（与排查脚本一致）：

```python
def mirror_obs(o):
    m = o.copy()
    m[0] = -o[0]; m[2] = -o[2]            # ang_vel roll/yaw 变号
    m[4] = -o[4]                          # gravity_y 变号
    m[7] = -o[7]                          # command_wz 变号
    m[9],  m[10] = o[10], o[9]            # theta0 L<->R
    m[11], m[12] = o[12], o[11]           # theta0_dot
    m[13], m[14] = o[14], o[13]           # L0
    m[15], m[16] = o[16], o[15]           # L0_dot
    m[17], m[18] = -o[18], -o[17]         # wheel_pos 交换并取负
    m[19], m[20] = -o[20], -o[19]         # wheel_vel 交换并取负
    m[21], m[24] = o[24], o[21]           # last_action theta L<->R
    m[22], m[25] = o[25], o[22]           # last_action l0   L<->R
    m[23], m[26] = -o[26], -o[23]         # last_action wheel 交换并取负
    return m

def mirror_act(a):
    return np.array([a[3], a[4], -a[5],  a[0], a[1], -a[2]])

# obs_history 是 5 帧 27 维拼接，逐帧套用 mirror_obs 即可。
```

### 4.3 镜像算子如何验证

镜像算子的正确性由两条独立证据交叉确认：

1. **理论自洽**：每条规则都能从"绕 x–z 平面镜像下，真矢量翻 y、赝矢量翻 x/z、左右量互换、
   镜像轴轮量取负"这一套统一原则推出（见上表"依据"列）。
2. **行为验证**：把对称化策略放回 MuJoCo 实跑，偏航被消除（下节）。若 `M_obs`/`M_act`
   推错，对称化非但不会消除偏航，反而会破坏直行——实测没有发生，反向印证算子正确。

### 4.4 修复效果（在 MuJoCo 实跑对比）

同一初始条件，分别用原始策略与对称化策略各跑 8 s，比较偏航：

| 工况 | 原始策略 偏航率均值 | 对称化后 | 降幅 | 备注 |
|---|---|---|---|---|
| vx=0 | +0.104 rad/s | +0.001 rad/s | **99%** | 最终机身高度一致 |
| vx=1.2 | +0.364 rad/s | +0.002 rad/s | **100%** | 最终机身高度一致，未损稳定性 |

原始 vx=1.2 实跑得到 +0.36 rad/s，与记录数据的 +0.40 rad/s 高度吻合，证明复现可信；
对称化后偏航几乎归零，且站立高度不变，说明该方案有效且不伤稳定性。

## 5. 方案菜单（按推荐度）

1. **【即时，先用】推理时镜像对称化**：已验证消除 99~100% 偏航，不动训练，
   sim2sim 与 sim2real 通用（两侧 27 维观测布局一致，算子可直接移植到 NUC 端）。
2. **【根治】重训时加左右镜像对称增强**（mirror data augmentation / mirror loss）：
   从源头让网络等变，是腿足 RL 的标准做法，但需重新训练。
3. **【兜底】外层偏航积分回正**：对 yaw rate 做积分纠偏；属打补丁，且策略已能看到
   yaw rate，不如前两者干净。
